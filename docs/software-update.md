# 软件更新与发布

安装版使用 electron-updater 的 NSIS 适配器，固定从公开仓库 dmibing/svnx 的 GitHub Releases 获取正式版本。发布配置不包含访问令牌。仅实际安装过程写入的 `resources/svnx-installed` 标记启用应用内安装；便携版、开发运行和解压目录运行只检查版本并提供发布页入口。通用状态机与 UI 不依赖 Windows 原生接口，其他平台后续可接入相应打包适配器。

用户主动检查、下载并确认重启安装；`autoDownload`、`autoInstallOnAppQuit`、`allowDowngrade`、`allowPrerelease` 均关闭。下载和 SHA-512 校验由框架执行，没有禁用代码签名校验。当前构建没有配置 Authenticode 证书，因此不将摘要校验称为发行者数字签名。正式安装位置由 NSIS 管理，自定义目录在后续升级时沿用；应用数据目录与安装目录分离，不删除用户设置。

`electron/software-update.cjs` 管理状态与取消下载。`electron/main.cjs` 仅接受固定操作名，不接受渲染层传入的更新地址、命令或文件路径；安装前检查 SVN 任务，并在安装准备期间拒绝启动新的 SVN 操作。用户未保存的冲突编辑需要在确认重启前保存。失败可以重试检查或手动下载安装包；不承诺安装过程断电后的自动回滚。

构建与发布：

1. `npm run dist:all` 先生成便携版，再生成安装版。便携脚本关闭发布元数据生成，避免覆盖安装版的 `latest.yml`。
2. `npm run release:audit` 检查应用归档中没有设置、备份、工作副本或测试运行数据，检查项目运行资源中没有当前用户的本机路径或常见凭据，并验证安装包与 `latest.yml` 的 SHA-512 一致。
3. `npm run release:publish` 再次执行检查，从本机 Git 凭据管理器临时读取发布凭据，仅通过 curl 标准输入发送授权头，不写文件、不写应用资源、不打印令牌。只上传明确列出的安装包、blockmap、便携包、SHA256SUMS.txt、latest.yml；先创建草稿，上传核对后才公开发布。已公开的版本禁止覆盖。

用户下载的应用只读取公开更新源，不需要 GitHub 令牌，不上传 SVN 地址、密码、工作副本或备份。GitHub 会收到常规更新请求的网络信息。发布工具的认证与客户端的匿名更新流程分离。

版本说明按需加载 Marked 与 DOMPurify，兼容 Markdown 和 GitHub 返回的 HTML。只保留段落、列表、标题、强调、代码和表格等展示标签，过滤属性、脚本、外部图片和嵌入内容；链接仅保留文字。安装版正常检查时隐藏发布页按钮，发生错误时提供该入口；便携版保留下载入口。

验证：状态机单元测试覆盖显式操作、去重、取消重试、损坏包拒绝、任务占用保护和便携版限制；`tests/desktop-software-update.mjs` 使用真实 electron-updater 在隔离缓存中下载本机测试数据，验证 SHA-512 与损坏数据拒绝，并验证 UI 二次确认。测试不会运行下载的测试文件。未来的实际跨版本安装仍需要在发布后随版本演进验证。
